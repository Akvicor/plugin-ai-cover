# AI 封面生成

为 Halo 博客提供 AI 封面图生成能力的插件。通过 [AI Foundation](https://github.com/halo-dev/plugin-ai-foundation) 调用语言模型理解文章，再由图片模型根据画面描述与用户提示词生成封面图，并上传到附件库。

## 功能特性

- 在默认文章编辑器顶部工具栏提供「AI 生成封面」入口，生成后预览并上传。
- 文章列表的 `···` 菜单提供后台生成：没有封面时显示「AI 补充封面」，已有封面时显示「AI 生成封面」，点击后在后台生成、保存附件并设置封面。
- 每篇文章同一时间只允许一个生图任务，任何入口的后续请求都会被拒绝并提示「该文章正在生成封面」。
- 标题默认由后端读取，提示词默认取插件设置；两者均可在编辑器的生成弹窗中修改。
- 手动生成由后端读取最新已保存正文，包括已完成的编辑器自动保存内容；发布后自动生成读取已发布正文。
- 生成前校验当前文章：标识无效、文章读取失败，或后台读取的标题与正文同时为空时，弹窗显示错误并终止本次生成，模型调用仅在校验通过后开始。
- 生成分两步执行：语言模型阅读文章标题与正文，输出画面描述；图片模型结合画面描述与用户提示词生成图片。两个模型均在插件设置中从 AI Foundation 选择。
- 生成结果支持预览与点击放大，桌面双栏、窄屏单栏显示；任一步生成失败都会结束任务并显示错误提示。
- 上传前可编辑包含扩展名的附件完整名称，选择存储策略与分组，通过 multipart 文件上传保存到附件库。
- 上传成功后自动将图片填入当前编辑器的封面，随文章的保存或发布操作持久化。
- 附件默认名称为 `文章标题-00.扩展名`，扩展名随图片媒体类型确定，例如 PNG 对应 `文章标题-00.png`。
- 可开启「发布时自动生成缺失封面」，文章正常发布后在后台完成生成、上传和封面设置；已有封面会被保留。
- 文章列表以徽标展示列表与发布触发任务的生成中、成功、跳过和失败状态，悬停查看原因和时间；成功后刷新一次列表，以 Halo 原生缩略图展示新封面。

## 环境要求

- Halo `>= 2.26.0`
- [AI Foundation](https://www.halo.run/store/apps/app-acslk9nu) `>= 1.0.0` 且 `< 2.0.0`
- AI Foundation 中已配置并启用可用的语言模型和图片生成模型
- 手动生成和任务状态查看面向 Halo 超级管理员，编辑器按钮、文章列表菜单与状态徽标按超级管理员权限展示；后端接口由 Halo 角色权限系统鉴权。

### 权限与第三方服务

生成封面会读取文章内容、调用站点配置的模型服务、写入附件和文章封面，任务查询也涉及站点内多篇文章。因此手动操作统一由超级管理员执行，插件 API 沿用 Halo 默认的超级管理员访问范围。

语言模型和图片模型的服务提供方，以站点在 AI Foundation 中配置并选择的服务商为准。服务额度、模型能力、计费及退款规则由对应服务商决定，调用费用由站点使用者承担。可以关闭「发布时自动生成缺失封面」以停止后续发布触发的调用；停用本插件会取消本实例内正在运行的任务，服务商已接收的请求仍按其规则处理。服务订阅和凭据可在服务商后台取消或撤销。插件问题通过 [GitHub Issues](https://github.com/akvicor/plugin-ai-cover/issues)反馈，模型计费问题通过所选服务商的支持渠道处理。

## 安装

1. 在 Halo 应用市场安装并启用 [AI Foundation](https://www.halo.run/store/apps/app-acslk9nu)，完成服务商、语言模型与图片生成模型配置。
2. 在 Halo Console 的插件页面上传本插件的 JAR 并启用。自行构建的方法见「构建」章节。
3. 打开插件设置的「封面生成设置」，选择文章理解模型和图片生成模型，填写默认提示词，设置图片宽高比、默认存储策略与默认分组。

## 使用

1. 打开或新建文章，先保存需要用于生成封面图的内容，再在编辑器顶部工具栏点击「AI 生成封面」。
2. 按需修改文章标题与提示词，点击「生成」。弹窗中的标题用于本次生成和附件默认命名。
3. 生成完成后在预览区查看图片，点击图片可放大查看。
4. 点击「上传」，在确认框中修改附件完整名称、存储策略与分组，确认后上传到附件库，并自动填入当前文章封面。
5. 在编辑器中保存或发布文章，使封面设置生效。

### 从文章列表生成

1. 在目标文章行的 `···` 菜单点击：
    - 文章没有封面时为「AI 补充封面」：生成期间如果文章已经设置了封面，保留该封面并跳过。
    - 文章已有封面时为「AI 生成封面」：生成后直接替换封面。
2. 后台读取文章最新已保存的正文，使用插件设置中的模型、默认提示词、存储策略和分组生成图片并保存附件，附件归属于文章作者，名称为 `文章标题-00.扩展名`。写入封面时只修改封面字段，文章其他字段的并发修改会被保留。
3. 文章行的徽标显示生成中、成功、跳过或失败，悬停查看原因和时间。成功后列表刷新一次，标题左侧显示 Halo 原生缩略图，分页和筛选保持不变。
4. 附件已上传但最终没有设置为封面（跳过或写入失败）时，后台按附件标识删除该附件；文章当前封面已指向该附件时保留。

### 发布后自动补齐封面

1. 由超级管理员保存模型、默认提示词、存储策略和分组配置，开启「发布时自动生成缺失封面」。该开关默认关闭，开启后发布无封面的文章可能产生模型调用费用。
2. 文章发布成功后，后台按「AI 补充封面」的同一流程生成并设置封面，读取已发布正文。文章正在生成封面时跳过本次发布事件。
3. 失败原因显示在文章行徽标的悬停说明中，文章保持发布状态。修正配置后，可以从列表菜单或编辑器中重新生成。

自动补封面由上述站点配置控制，也适用于普通编辑者发布的文章；手动入口的可见权限与后台发布事件分别处理。

### 任务状态与锁

- 文章级锁与任务状态保存在当前 Halo 实例内存中。编辑器任务锁定到图片生成完成；列表和发布任务锁定到封面设置完成或失败。锁随任务结束、插件停止或重启释放。
- 文章列表和编辑器窗口共用一次状态查询，只在存在生成中的任务时定时刷新，离开页面后停止。关闭窗口或切换页面不影响后台任务。
- 已结束的状态从结束时起保留 15 分钟，在下次查询时清理；插件停止或重启会清除全部状态。附件及已设置的文章封面独立保存在 Halo 中。
- 编辑器生成的图片在上传成功后从服务端内存释放；未上传时随状态过期一并清除。

## 插件设置

| 配置项                   | 说明                                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------------------- |
| 发布时自动生成缺失封面   | 默认关闭；文章发布成功后后台补图，进度在文章列表及生成弹窗查看，失败不影响发布                      |
| 默认提示词               | 编辑器生成弹窗自动填充并可修改；列表和发布后的后台生成直接使用；与画面描述一起交给图片生成模型      |
| 文章理解模型（语言模型） | 第一步阅读文章标题与正文并生成画面描述，从 AI Foundation 中已启用的语言模型中选择                   |
| 图片生成模型             | 第二步根据画面描述与用户提示词出图，从 AI Foundation 中已启用的图片生成模型中选择                   |
| 图片宽高比               | 默认 `16:9`，另有 `3:2`、`4:3`、`1:1`、`9:16`；作为请求参数传给模型，实际结果取决于模型及适配器支持 |
| 默认存储策略             | 上传封面图时默认使用的存储策略                                                                      |
| 默认分组                 | 上传封面图时默认使用的分组，可留空表示不分组                                                        |

## 数据与隐私

- 文章标题与正文由 Halo 后端读取。正文转换为纯文本后，最多取前 8000 个字符发送给所选语言模型的服务商；本次生成使用的标题优先取弹窗中的填写值。
- 语言模型返回的画面描述与用户提示词会发送给所选图片生成模型的服务商，用于生成图片。两步调用的数据处理取决于各自服务商的政策。
- 编辑器生成的结果返回浏览器用于预览；确认上传后，图片保存到指定存储策略和分组，附件归属于当前登录用户。列表和发布后的后台生成直接通过 Halo 附件服务在内存中保存并设置封面，不写临时文件，附件归属于文章作者。
- 插件的 DEBUG 日志只记录模型标识、处理阶段、警告数量和检测出的图片格式；失败日志记录任务、文章或附件标识及错误类型。各日志级别均不输出文章标题、正文、提示词、生成的画面描述、供应商警告原文或异常堆栈，避免内容通过服务端日志流转。模型服务商及 AI Foundation 自身的数据与日志策略由相应服务管理。
- 任务状态和未上传的预览图片按「任务状态与锁」中的期限保存在实例内存中；上传后的图片保存在所选附件存储中，随 Halo 附件管理流程保留或删除。服务商侧的数据留存、删除与撤销授权按其政策处理。

## 升级与停用

- 从旧版本升级时，在 Halo 插件页面更新本插件 JAR。插件 ID、设置及配置关联保持一致，已保存的文章封面和附件继续使用；新增的发布自动补封面默认关闭。
- 升级前等待生成任务结束并上传需要保留的预览图。更新、停用或重启会取消实例内任务并清除内存状态，尚未上传的预览图需要重新生成。
- 停用或卸载插件后，已保存的封面与附件仍由 Halo 管理。需要清理时，先在文章中移除或替换封面，再通过 Halo 附件库删除对应文件。

## 开发

开发工具：JDK 21、Node.js `>= 22.12.0`、pnpm `10.33.0`。启动本地 Halo 开发环境还需要 Docker。

将 AI Foundation 插件 JAR 放入 `workplace/plugins/`，在项目根目录启动 Halo 后确认依赖插件已启用：

```bash
./gradlew haloServer
```

另开终端启动前端构建监听：

```bash
cd ui
pnpm install
pnpm dev
```

在项目根目录生成前端 API 客户端。该任务复用运行中的 Halo 服务，服务中应已安装并启用本插件和 AI Foundation，并提供 `/v3/api-docs/aiCoverApis` 文档分组：

```bash
./gradlew generateApiClient
```

也可以从内存 WebFlux 路由测试生成本插件 OpenAPI，再交给同一客户端生成任务处理：

```bash
./gradlew test --tests com.akvicor.aicover.endpoint.CoverOpenApiTest
./gradlew generateApiClient -x generateOpenApiDocs
```

该测试只加载本插件路由与文档组件，文章、模型和附件服务使用 mock。生成文档位于 `build/api-docs/`。

在项目根目录执行单元测试、类型检查及静态检查：

```bash
make verify
```

## 构建

在项目根目录执行：

```bash
./gradlew build
```

构建产物位于 `build/libs`。

准备指定版本的发布制品时，使用 Makefile 的版本参数：

```bash
make build VERSION=0.2.0 OUTPUT=build/release/0.2.0/plugin-ai-cover-0.2.0.jar
```

该命令将版本写入插件元数据，并将包含前端资源的 JAR 放入指定目录。

## 版本说明

各版本的功能、权限与数据处理变化见 [CHANGELOG.md](./CHANGELOG.md)。发布时将对应版本说明填写到 GitHub Release 和应用市场，并使用同一版本源码构建的 JAR。
